### 3.1 SSO 登录跳转测试（GEOFlow ↔ LumoraCite）

**测试目标**：验证 GEOFlow 作为 IdP、LumoraCite 作为 SP 的单点登录流程。

**步骤**：

1. 打开 http://localhost:3000/（Dashboard）
2. 页面应显示登录界面，有"客户登录"和"管理员登录"两个标签
3. 点击 **"管理员登录"** 标签
4. 点击 **"GEOFlow SSO 登录"** 按钮
5. 浏览器跳转到 GEOFlow 登录页（http://localhost:18080/...）
6. 输入用户名 `admin`，密码 `admin123456`，点击登录
7. 登录成功后，浏览器自动跳转回 Dashboard
8. Dashboard 应显示管理员已登录状态

**预期结果**：整个流程无需手动输入 URL，自动跳转完成。

### 3.2 GEOFLOW → LumoraCite 信息互通测试

**测试目标**：验证 LumoraCite 能读取 GEOFlow 分发的文章数据。

**步骤**：

### 3.3 GEOFLOW → GEOwebsite 推送测试

**测试目标**：验证 GEOFlow 推送文章到 GEOwebsite 的 webhook 功能。

**步骤**：

1. 确保 GEOwebsite 运行中（http://localhost:3001/）
2. 登录 GEOFlow 后台 http://localhost:18080/geo_admin/login
3. 创建或选择一篇已有文章
4. **分发/发布文章**，目标选择 GEOwebsite（outbound private target）
5. GEOFlow 通过 GenericHttpApiPublisher 推送 JSON 到 `http://localhost:3001/api/geoflow-webhook`
6. 检查 GEOwebsite 是否收到文章

**验证方式**：

```bash

  -H "Content-Type: application/json" \

  -d '{
    "version": "1.0",
    "source": "geoflow",
    "event": "article.publish",
    "article": {
      "id": 999,
      "slug": "test-push-article",
      "title": "推送测试文章",
      "content": "这是一篇测试文章内容。",
      "excerpt": "测试摘要"

# 方法2：访问 GEOwebsite 查看文章
# 打开 http://localhost:3001/zh/posts/test-push-article

# 方法3：检查 GEOwebsite 数据库
```

### 3.5 同库运行验证

**测试目标**：确认 GEOFlow 和 LumoraCite 共享同一 PostgreSQL 实例，通过 schema 隔离互不干扰。

**验证方式**：

```bash
# 1. 确认两个 schema 存在于同一数据库
docker exec geoflow-postgres psql -U geo_user -d geo_flow -c \
  "SELECT schema_name FROM information_schema.schemata WHERE schema_name IN ('public','monitor');"

# 2. 确认 GEOFlow 只能访问 public schema
docker exec geoflow-postgres psql -U geo_user -d geo_flow -c \
  "SELECT count(*) FROM public.articles;"

# 3. 确认 LumoraCite 能访问 monitor schema
docker exec geoflow-postgres psql -U geo_user -d geo_flow -c \
  "SELECT count(*) FROM monitor.clients;"

# 4. 确认 GEOwebsite 用独立数据库
docker exec geo-pg-local psql -U geo_owner -d geowebsite -c \
  "SELECT count(*) FROM payload.posts;"
```

## 四、服务启停命令

```bash
# 1. 启动 GEOFlow 容器（postgres 已运行则跳过）
docker start geoflow-postgres geoflow-redis geoflow-app geoflow-scheduler geoflow-queue

docker start geo-pg-local

# 5. 启动 GEOwebsite（端口 3001）
cd "/home/tishensnoopy/GEOwebsite" && npm run dev -- -p 3001 &
```

### 4.2 停止全部服务

```bash
# 停止容器
docker stop geoflow-app geoflow-scheduler geoflow-queue geoflow-redis
docker stop geo-index-monitor-local geo-redis-local

# 停止前端（找到进程并 kill）
```

## 五、常见问题

### Q1: GEOFlow 推送到 GEOwebsite 失败？

检查：
1. GEOwebsite 是否运行：`curl http://localhost:3001/api/geoflow-webhook -X POST -H "Authorization: Bearer 38a2ab65af709848f0553bc668f58913" -d '{"event":"health.check"}'`
2. GEOFlow .env 中 `GEOFLOW_OUTBOUND_PRIVATE_TARGETS` 是否指向 `http://localhost:3001/api/geoflow-webhook`
3. `GEOFLOW_OUTBOUND_SIGNING_KEY` 和 GEOwebsite 的 `GEOFLOW_WEBHOOK_TOKEN` 是否一致
4. 修改 .env 后是否重启了 geoflow-app：`docker restart geoflow-app`

### Q2: SSO 登录跳转失败？

检查：
1. GEOFlow 后台是否可访问：`curl http://localhost:18080/geo_admin/login`
2. SSO 重定向链是否正确：`curl -s -o /dev/null -w "%{redirect_url}" http://localhost:8090/sso/login`
3. GEOFlow admin 凭据是否正确：admin / admin123456

### Q3: Dashboard 显示"客户账号或密码错误"？

- admin/admin123456 是 **GEOFlow 后台** 凭据，不是 LumoraCite 客户凭据
- LumoraCite 客户登录用：demo / demo123456
- LumoraCite 管理员通过 **SSO 登录**（管理员标签页）

### Q4: GEOwebsite 首次访问很慢？

- Next.js Turbopack 首次编译需要 30-80 秒
- 后续访问会快很多（已编译的页面 <1 秒）

### Q5: 端口冲突？

- Dashboard 前端：3000（vite 默认）
- GEOwebsite：3001（指定 `-p 3001` 避开 Dashboard）
- 如果 3000 被占用：`lsof -i:3000` 查看进程
