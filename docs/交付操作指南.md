# GEOFlow + LumoraCite 交付操作指南

> 版本：v1.0 | 更新日期：2026-07-28 | 适用版本：GEOFlow v2.1.2 + LumoraCite

## 一、系统概述

### 1.1 GEOFlow（内容分发引擎）

GEOFlow 是一个 AI 驱动的内容分发引擎，负责：

- **文章内容管理**：创建、编辑、发布、分类、关键词管理
- **多渠道分发**：WordPress、GitHub Pages、自定义渠道
- **AI 模型配置**：聊天模型（DeepSeek）、Embedding 模型（智谱 Embedding-3）
- **SSO 身份提供者**（IdP）：为 LumoraCite 提供统一登录
- **SEO/GEO 优化**：结构化数据、meta 标签、AI 搜索引擎优化

**技术栈**：Laravel (PHP 8.2) + PostgreSQL + Redis + Blade/Livewire

### 1.2 LumoraCite（监测平台）

LumoraCite 是一个内容监测平台，负责：

- **分发记录管理**：手动添加 + GEOFlow 自动同步
- **搜索引擎收录扫描**：百度/头条/搜狗/360/必应（5 引擎）
- **AI 采信监测**：DeepSeek 生成问题 + 多模型引用检测
- **数据看板**：5 个可视化图表
- **PDF 报告导出**：Playwright + Chromium 渲染
- **扫描活动窗口**：终端样式实时日志

**技术栈**：FastAPI (Python 3.11) + Vue 3 + Element Plus + PostgreSQL + Redis

## 三、GEOFlow 功能详解

### 3.1 内容管理

- **文章 CRUD**：创建、编辑、删除、归档
- **分类管理**：6 个预设分类
- **作者管理**：2 个预设作者
- **关键词管理**：JSON 格式存储
- **SEO 元数据**：meta_description、og:title、canonical URL
- **内容正文**：支持 HTML 和 Markdown

### 3.2 分发渠道

| 渠道类型 | 说明 | 配置方式 |
|----------|------|----------|
| WordPress | 推送到 WordPress 站点 | 配置 XML-RPC/REST API |
| GitHub Pages | 推送到 GitHub 仓库 | 配置 GitHub Token + 仓库 |
| 自定义渠道 | API 推送 | 配置目标 URL + Token |

**分发状态**：`synced`（已同步）/ `pending`（待同步）/ `failed`（失败）

### 3.3 AI 模型配置

GEOFlow 后台支持配置两类 AI 模型：

**聊天模型（Chat）**：
- DeepSeek（model_id: `deepseek-chat`）
- API URL: `https://api.deepseek.com/v1`
- 用途：内容生成、问题推断

**Embedding 模型**：
- 智谱 Embedding-3（model_id: `embedding-3`）
- API URL: `https://open.bigmodel.cn/api/paas/v4`
- 用途：知识库向量化

**模型测试**：点击"测试连接"验证 API 可达性。测试失败时会显示上游错误详情（如余额不足 code=1308、套餐到期 code=1309、速率限制 code=1302）。

### 3.4 GitHub Pages 发布

GEOFlow 支持将文章自动发布到 GitHub Pages：

1. 在 GEOFlow 后台 → 分发渠道 → 添加 GitHub 渠道
2. 配置：
   - GitHub 仓库地址
   - GitHub Personal Access Token
   - 分支名（通常 `gh-pages` 或 `main`）
3. 发布文章时选择 GitHub 渠道
4. 文章自动推送到仓库，GitHub Pages 自动部署

**GEOFlow 开源仓库**：https://github.com/yaojingang/GEOFlow

### 3.5 SSO 集成（IdP）

GEOFlow 作为 SSO 身份提供者（IdP），为 LumoraCite 提供统一登录：

- **授权端点**：`http://localhost:18080/sso/authorize`
- **用户信息端点**：`http://localhost:18080/sso/userinfo`
- **认证方式**：一次性 code（Redis 存储，60 秒过期）
- **安全机制**：CSRF state 参数防攻击

## 四、LumoraCite 功能详解

### 4.1 分发记录管理

**数据来源**（合并查询）：
1. **GEOFlow 分发**：`public.article_distributions`（跨 schema JOIN）
2. **手动录入**：`monitor.manual_distributions`

**手动添加文章流程**：
1. 管理员输入文章 URL + 关联客户
2. 系统自动抓取文章标题和快照
3. 创建 `IndexResult` 记录（文章列表立即可见）
4. 异步触发收录扫描（不阻塞响应）

### 4.2 搜索引擎收录扫描

**5 个搜索引擎**：百度、头条、搜狗、360、必应

**扫描逻辑**：
- 从文章 URL 提取域名
- 执行 `site:domain.com` 查询
- 检测验证码页面（避免误判）
- 最多重试 1 次（应对临时网络错误）
- 记录详细日志（结果数、失败原因）

**扫描状态**：`pending` / `indexed` / `not_indexed` / `error`

### 4.3 AI 采信监测

**5 步检测流程**：
1. **内容抓取**：浏览器 UA + headless Chrome 回退
2. **目的推断**：DeepSeek 分析文章主题
3. **问题生成**：DeepSeek 生成自然语言问题
4. **模型探测**：验证引用检测模型的联网能力（重试 2 次 + OR 标准）
5. **引用检测**：多模型执行搜索，匹配文章 URL

**命中分类**：
- `exact`：AI 回答中包含文章 URL
- `partial`：AI 回答中包含文章域名但非具体 URL
- `none`：AI 回答中未提及文章

### 4.4 数据看板（5 个图表）

1. **统计卡片**：总文章数、已收录数、采信命中率
2. **多引擎收录趋势**：折线图，按日期展示 5 引擎收录变化
3. **AI 采信分布饼图**：exact / partial / none 占比
4. **引擎收录对比柱状图**：各引擎收录数量对比
5. **来源分布环形图**：GEOFlow 分发 vs 手动录入占比

### 4.5 PDF 报告导出

- **渲染引擎**：Playwright + Chromium（确保格式完整）
- **报告内容**：
  - 公司 logo / 水印
  - 文章快照（标题 + URL + 前 300 字正文）
  - 收录状态（5 引擎 + 检测时间）
  - AI 采信详情（模型标签、命中类型、完整 AI 回答文本）
- **格式要求**：图片不跨页，排版一致

### 4.6 扫描活动窗口（终端日志）

点击"批量检测"后自动打开终端样式窗口，实时显示：

- **进度条**：已处理 / 总数 + 成功 / 失败计数
- **状态标签**：运行中 / 已完成 / 失败
- **终端日志**：
  - `[收录检测] 开始: {url}` — 灰色
  - `[收录检测] 完成: {url}` — 绿色
  - `[收录检测] 失败: {url} - {错误}` — 红色
  - `[AI采信检测] 开始/完成/失败: {url}` — 同上
- **自动滚动**：新日志自动滚动到底部
- **轮询间隔**：2 秒

## 五、两套系统间的数据交换

### 5.1 数据库共享

两个系统共享同一个 PostgreSQL 实例（`geoflow-postgres` 容器），通过 schema 隔离实现数据分离。

### 5.2 Schema 隔离

**public schema（GEOFlow）**：
- `articles` — 文章内容
- `article_distributions` — 分发记录
- `distribution_channels` — 分发渠道
- `ai_models` — AI 模型配置
- `users` — 用户
- 共 59 张表

**monitor schema（LumoraCite）**：
- `clients` — 客户
- `client_sites` — 客户站点（domain → client_id 映射）
- `manual_distributions` — 手动录入记录
- `index_results` — 收录检测结果
- `citation_results` — AI 采信检测结果
- `system_config` — 系统配置
- `admin_users` — 管理员
- `admin_audit_logs` — 审计日志
- `scan_tasks` — 扫描任务（内存存储，非 DB）

### 5.3 跨 schema JOIN

LumoraCite 的 `DistributionQueryService` 通过跨 schema JOIN 查询 GEOFlow 分发数据：

```
SELECT dist.*, article.*, channel.*, index_result.*
FROM public.article_distributions dist
JOIN public.articles article ON article.id = dist.article_id
LEFT JOIN public.distribution_channels channel ON channel.id = dist.distribution_channel_id
LEFT JOIN monitor.index_results index_result ON index_result.url = dist.remote_url
WHERE dist.status = 'synced' AND dist.action != 'delete'
```

**domain 匹配机制**：
1. 从 GEOFlow 分发记录的 `remote_url` 提取 domain
2. 查 `monitor.client_sites` 表，通过 domain 匹配找到 `client_id`
3. 只返回已登记 domain 的分发记录

### 5.4 SSO 集成

**角色分工**：
- GEOFlow = IdP（身份提供者，负责认证）
- LumoraCite = SP（服务提供者，依赖 IdP 认证）

**SSO 完整流程**：

```
用户访问 Dashboard (localhost:3000)
    │
    ▼
未登录 → 重定向到 SSO 登录 (localhost:8090/sso/login)
    │
    ▼
生成 state 参数 → 重定向到 GEOFlow authorize (localhost:18080/sso/authorize?state=xxx)
    │
    ▼
GEOFlow 检查用户登录状态
    │
    ├── 已登录 → 生成一次性 code → 回调 LumoraCite
    │
    └── 未登录 → GEOFlow 登录页面 → 登录成功 → 生成 code → 回调
    │
    ▼
LumoraCite 用 code 换取 userinfo (localhost:18080/sso/userinfo)
    │
    ▼
创建 LumoraCite 会话 → 跳转 Dashboard 首页
```

**安全机制**：
- CSRF state 参数（防跨站请求伪造）
- 一次性 code（Redis 存储，60 秒过期）
- Cache-Control 头（防浏览器缓存旧响应）

## 七、操作指南

### 7.1 启动服务

```bash
# 1. 启动所有 Docker 容器
docker start geoflow-postgres geoflow-redis geo-redis-local \
  geoflow-app geoflow-queue geoflow-scheduler geo-index-monitor-local

# 2. 启动 Dashboard 前端
cd "/home/tishensnoopy/GEO FLOW+LUMORA CITE/dashboard"
npm run dev

# 3. 验证服务状态
docker ps --format "table {{.Names}}\t{{.Status}}"
curl http://localhost:8090/api/v1/health  # 应返回 {"status":"healthy"}
```

### 7.2 停止服务

```bash
# 停止所有 Docker 容器
docker stop geo-index-monitor-local geoflow-app geoflow-queue \
  geoflow-scheduler geoflow-redis geoflow-postgres geo-redis-local

# 停止 Dashboard 前端
pkill -f "node.*vite"
```

### 7.3 添加文章监测

2. 进入"分发记录"页面
3. 点击"添加链接"按钮

**系统自动执行**：

2. 抓取文章标题和快照
3. 创建 `index_results` 记录（文章列表立即可见）

**批量扫描**：
1. 在"分发记录"页面勾选要扫描的链接
2. 点击"批量检测"按钮
3. 选择检测类型：

   - 两者都检测

- 自动打开终端样式窗口
- 实时显示扫描进度和日志
- 2 秒轮询更新

**立即扫描所有**：
- POST `/api/v1/scan/trigger/index` — 触发所有待检测 URL 的收录扫描
- POST `/api/v1/scan/trigger/citation` — 触发所有待检测 URL 的采信扫描

- 路径：Dashboard → 文章列表

## 八、常见问题

### 8.1 GEOFlow 模型测试返回 429

**原因**：智谱 API 返回 429，可能原因：
- 账户余额已用完（code: 1308）
- GLM Coding Plan 套餐到期（code: 1309）
- 速率限制（code: 1302）
- 每日/每周/每月限额（code: 1304/1310）

**解决**：
1. 查看错误详情（已修复，现在显示上游错误码和消息）
2. 登录智谱控制台检查余额和套餐
3. 用 cURL 直接测试确认：
   ```bash
   curl -X POST https://open.bigmodel.cn/api/paas/v4/embeddings \
     -H "Authorization: Bearer YOUR_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"model":"embedding-3","input":"test"}'
   ```

### 8.2 文章列表和分发记录不同步

**原因**：手动添加文章时未创建 `index_results` 记录

**已修复**：手动添加文章时自动：
1. 创建 `IndexResult` 记录（pending 状态）
2. 文章列表立即可见
3. 异步触发收录扫描

### 8.3 AI 采信扫描频繁失败

**原因**（已修复）：
1. ~~模型探测零重试+严标准~~ → 已改为重试 2 次 + OR 标准
2. ~~内容抓取 UA 被屏蔽~~ → 已改为浏览器 UA + 403 触发 headless 回退
3. ~~site: 查询语法错误~~ → 已改为使用域名查询

**仍需检查**：
- `system_config` 中的 API Key 是否配置
- 引用检测模型是否可达

### 8.4 收录扫描结果不准

**已修复**：`site:` 查询现在使用域名（`site:example.com`）而非完整 URL

### 8.5 SSO 登录失败

**检查**：
1. GEOFlow 服务是否运行（http://localhost:18080）
2. SSO_JWT_SECRET 是否正确配置
3. SSO_GEOFLOW_USERINFO_URL 是否指向正确的容器内部地址
4. Redis 是否健康（SSO state 存储）
