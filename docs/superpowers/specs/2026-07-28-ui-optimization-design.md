# LumoraCite Dashboard UI 优化设计

- **日期**：2026-07-28
- **状态**：已确认，待实现
- **范围**：Dashboard 前端全量 UI 优化（A 信息密度 + B 视觉层次与动效 + C 响应式移动端）
- **设计语言**：深化当前 Ink & Signal（衬线体 + 信号青 + 宣纸白 + 雷达动画）

## 1. 背景与目标

### 1.1 当前状态

Dashboard 已有完整的 Ink & Signal 设计系统（[tokens.css](file:///home/tishensnoopy/GEO%20FLOW+LUMORA%20CITE/dashboard/src/styles/tokens.css)），具备独特视觉语言，但存在以下不足：

- 导航栏较朴素，缺层次
- 统计卡片信息密度偏低（仅主数字 + 名称）
- 表格页（分发记录）较单调（纯文字 + tag 状态）
- 移动端适配未优化（无断点、无底部 Tab）
- 扫描活动窗口可更直观（当前是对话框，用户反馈"全是黑盒"）

### 1.2 目标

| 方向 | 目标 |
|------|------|
| A 信息密度 | 每屏看到更多有效信息（统计卡片 4 层信息 + 表格状态可视化 + 图表交叉筛选） |
| B 视觉层次 | 让界面更有"监测平台"的科技感（侧栏布局 + 扫描状态指示 + 微动效 + 全屏扫描面板） |
| C 响应式 | 桌面和移动并重（三层断点 + 底部 Tab + 表格转卡片 + 触摸友好） |

### 1.3 非目标

- 不重写后端 API（仅消费现有接口）
- 不更换设计语言（保留 Ink & Signal）
- 不增加新页面（仅优化现有页面）
- 不做 PWA 离线支持

## 3. 信息密度设计（A 方向）

### 3.1 统计卡片：4 层信息结构

每张卡片包含 4 层信息：

```
┌─────────────────────────────────────┐
│ 01 / 04                  分发总数    │  ← 层 1：序号标签 + 名称
│                                     │
│  327  ↑12% vs 上周                  │  ← 层 2：主数字 + 同比箭头
│  ╱╲    ╱╲╱╲╱╲                       │  ← 层 3：30天 sparkline 趋势
│ ╱  ╲  ╱    ╲╱                       │
│                                     │
│ 本周 +18   本月 +47   待检测 12      │  ← 层 4：子指标（3 个）
└─────────────────────────────────────┘
```

**4 张卡片内容定义**：

| 卡片 | 主数字 | 同比 | sparkline 数据 | 子指标 |
|------|--------|------|----------------|--------|
| 01 分发总数 | 327 | ↑12% | 30天分发趋势 | 本周+18 / 本月+47 / 待检测12 |
| 02 已收录 | 245 | ↑8% | 30天收录趋势 | 本周+12 / 百度198 / 头条156 |
| 03 AI 采信 | 89 | ↑23% | 30天采信趋势 | 完全命中32 / 部分命中41 / 未命中16 |
| 04 平均收录率 | 73.4% | ↑5.2pp | 30天收录率 | 百度81% / 头条73% / 搜狗68% |

**视觉规格**：
- 左侧 3px 色条：ink (#1A1A1A) / signal (#0D9488) / violet (#4C1D95) / coral (#E76F51)
- 主数字：衬线体 28px，font-weight 700
- 同比箭头：上涨 `↑` 用 signal 绿，下跌 `↓` 用 coral 珊瑚
- sparkline：对应色条色，高度 32px，SVG 内联
- 子指标：11px ink-muted 灰色，三等分排列

### 3.2 分发记录表格：状态可视化 + 内联操作

**状态可视化**（替换原来的 el-tag）：

| 状态 | 视觉 | 含义 | 颜色 |
|------|------|------|------|
| `●收录` | 实心圆 | 5 引擎至少 1 个收录 | signal #0D9488 |
| `◐部分` | 半圆 | 部分引擎收录 | amber #F59E0B |
| `○未检` | 空心圆 | 未检测或全部未收录 | ink-muted #78716C |

**内联操作按钮**（hover 显示，移动端常驻）：
- `↗` 重新扫描（单条）
- `↘` 查看 AI 采信详情
- `⚙` 编辑/删除

**来源标签**：
- GEOFlow 同步：signal 绿底
- 手动录入：amber 黄底

### 3.3 图表增强

**多引擎收录趋势图**：
- 折线图增加数据点标签（hover 显示具体数值）
- 图例可点击交叉筛选（点击"百度"只看百度趋势）
- 增加对比基线（行业平均收录率虚线）

**AI 采信分布饼图**：
- 改为环形图（中间显示总采信数）
- 各扇区可点击下钻到具体文章列表

## 4. 视觉层次与动效（B 方向）

### 4.1 扫描状态指示器（侧栏底部）

```
侧栏底部（220px 模式）
┌────────────────────────┐
│ ──────────────────     │
│ ● 扫描中                │  ← 脉冲绿点 + 文字
│ 2 任务运行中            │  ← 任务数
│ [查看 →]               │  ← 点击打开扫描面板
└────────────────────────┘
```

**三态设计**：
- **空闲态**：灰点 + "暂无任务"
- **运行态**：脉冲绿点（与登录页雷达同步动效，2s 周期）+ "N 任务运行中"
- **完成态**：3 秒内显示 ✓ + "扫描完成 N 成功"，之后回到空闲

### 4.2 卡片悬浮动效

```
默认态                    Hover 态
┌─────────────┐          ┌─────────────┐
│ 卡片内容    │          │ 卡片内容    │ ↑
│             │   →      │             │ 阴影加深
└─────────────┘          └─────────────┘ translateY(-2px)
                         + border-color: signal 20%
```

- 位移：`translateY(-2px)`，过渡 200ms ease-out
- 阴影：从 `0 1px 2px rgba(0,0,0,0.04)` → `0 8px 24px rgba(13,148,136,0.12)`
- 边框：从透明 → `rgba(13,148,136,0.2)`

### 4.3 信号条增强（顶栏）

- 信号流横向滚动（CSS animation，40s 一轮，hover 暂停）
- 新事件加入时从右侧滑入
- 点击信号条可展开完整事件列表

### 4.4 扫描活动面板（右侧滑出）

**触发方式**：点击"立即收录扫描"/"立即 AI 采信扫描"按钮 → 右侧滑出全屏面板

**面板结构**：

```
┌──────────────────────────────────────────────┐
│  扫描运行状态  [×]                          │  ← 头部 48px
├──────────────────────────────────────────────┤
│  [进度环 67%]  4/6 已处理  ✓3 ✗1            │  ← 进度区 80px
│  类型: 收录扫描  耗时: 12.3s                 │
├──────────────────────────────────────────────┤
│  引擎状态                                    │  ← 引擎卡片 100px
│  ● 百度 ✓  ● 头条 ✓  ● 搜狗 ⏳  ● 360 ◌  ● 必应 ◌│
├──────────────────────────────────────────────┤
│  > 10:32:15 [INFO] 扫描任务已启动...         │  ← 终端日志区
│  > 10:32:16 [INFO] 开始检测: https://...     │     （自动滚动）
│  > 10:32:18 [SUCCESS] 百度收录确认           │
│  > 10:32:20 [WARN] 搜狗触发验证码, 重试中... │
│  > ▌                                        │     （光标闪烁）
└──────────────────────────────────────────────┘
```

**面板规格**：
- 宽度：桌面 50% / 平板 60% / 移动 100%
- 滑出动画：transform translateX(100%) → 0，300ms ease-out
- 背景遮罩：rgba(0,0,0,0.3)，点击关闭
- 终端日志区：monospace 字体，自动滚动到底部，光标闪烁

## 7. 实施约束

### 7.1 不变项

- 保留现有路由结构（/dashboard, /distributions, /articles, /clients, /settings）
- 保留现有 API 调用（仅调整响应数据的展示方式）
- 保留 Ink & Signal 设计语言（衬线体 + 信号青 + 宣纸白）
- 保留 Element Plus 组件库（仅样式覆盖，不更换）
- 保留 ECharts 图表库

### 7.2 数据需求

统计卡片的同比和 sparkline 需要 30 天历史数据。**经检查，当前后端不提供趋势数据 API**（仅有 `/api/v1/admin/dashboard/stats` 返回汇总数据）。

**处理方案**（二选一，实现阶段决定）：
- **方案 A（推荐）**：后端新增 `/api/v1/admin/dashboard/trend?days=30` 接口，返回各指标的每日数据点。前端 sparkline 消费此接口。
- **方案 B（降级）**：前端仅展示当前主数字 + 同比（需要后端在 stats 接口增加 `last_week` / `last_month` 字段），sparkline 暂时用静态占位图。

无论哪种方案，**同比数据**（vs 上周）都需要后端扩展 stats 接口返回对比值。这是本次 UI 优化的前置依赖。

### 7.3 性能约束

- 前端构建产物体积不超过当前 2.7M
- 首屏加载（LCP）不超过 2 秒
- 扫描面板滑出动画不掉帧（60fps）

## 9. 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 30 天趋势数据 API 不存在 | 先检查后端，必要时扩展（已列入前置依赖） |
| Element Plus 样式覆盖冲突 | 使用 CSS 变量 + scoped 样式，避免 !important |
| 移动端表格转卡片工作量大 | 提取 `ResponsiveTable.vue` 组件，统一处理 |
| 扫描面板与现有 ScanTerminal.vue 冲突 | 重构 ScanTerminal.vue 为 ScanPanel.vue，保留逻辑替换 UI |
| sparkline SVG 性能 | 限制数据点 ≤ 30 个，requestAnimationFrame 渲染 |
